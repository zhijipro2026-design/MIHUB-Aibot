# 米家全屋：家庭状态、场景与区域自动化

> 依赖：设备台账见 `references/backup.md`（`device_registry.py`）；节点与平台约束见 `references/rule-kit.md`；写入网关见 `references/console.md` 或 MijiaFlow。

## 第 0 步（必须）：客户先完成入网和命名，AI 再读

AI 读设备之前，客户要先在米家 App 里完成两件事：全部设备入网，并按下面的规则填好名称和房间。命名没检查完，就不进入后面的步骤。AI 先把下面的检查清单发给客户，再用 `scripts/naming_check.py` 扫一遍台账，有问题的设备逐条请客户改名。

| 接法 | 怎么命名 | AI 怎么理解 |
| --- | --- | --- |
| 智能开关 + 普通灯 | 开关的那个键直接用灯的名字，**名字里写清灯具类型**，如「客厅主灯」「客厅筒灯」「客厅射灯」「电视墙灯带」 | 这个键就是这盏灯，开关它的继电器就是开关灯；按灯具类型分层（泛照明/重点照明/补光/氛围），氛围场景按层开关 |
| 智能开关 + 智能灯 | 开关键设为**无线模式**，并设为**来电自己上电**（通电默认打开），键按位置命名，如「客厅门口-左键」；智能灯用灯的名字 | 键只发事件，用规则去控制智能灯；不要去断这个键的继电器 |
| 混合 | 同一个开关上每个键分别按上面两种规则处理 | 按每个键的实际接法分别对待 |

检查清单（发给客户）：
- 每台设备都分好了房间，没有留在「默认房间」
- 没有出厂名，比如「米家智能开关」「Xiaomi Light」或带一串型号数字的名字
- 同一房间里没有重名
- 多键开关的每个键都有名字，并且能看出接的是普通灯（用灯名）还是无线键（用位置名）
- 接普通灯的键名写清灯具类型：主灯、吸顶灯、筒灯、灯槽、吊灯、射灯、轨道灯、画灯、洗墙灯、台灯、落地灯、床头灯、镜前灯、灯带、地脚灯、小夜灯
- 带智能灯的开关键已设为无线模式和来电自己上电

注意：MijiaFlow 读不到每个键的自定义名称，键名要从规则画布卡片或客户确认中补到台账里。

## 第 1 步：设备调试（开关的有线/无线、双控、场景键）

命名检查通过后、做场景之前，按 `references/commissioning.md` 把开关调好：接普通灯的键（包括双控的主开关）保持有线；接智能灯的键改无线并设来电上电；场景键、双控副开关改无线。体检报告的「设备调试清单」逐键列出该怎么设。改无线用一条一次性规则写属性（`build_switch_mode_rule`），客户同意后写入、启用一次、读回核对，再停用或删掉。

## 第 2 步：设置变量（全屋家庭模式 + 每个区域的模式、亮度、色温）

场景不只是批量开关灯，还要**记住现在是什么状态**。用户定的做法：

- **全屋家庭模式**（`VhomeMode01`，名「家庭模式」）只放跨区域的状态：在家、离家、全屋睡眠、起床、访客。
- **区域变量**：客厅、餐厅、卧室这类区域各三个，用 `area_variables("客厅")` 一次拿到：
  - 「客厅模式」（文字，`Vareaxxxxxx`）
  - 「客厅亮度」「客厅色温」（数字，`Vbrixxxxxxx`、`Vcctxxxxxxx`），灯光跟随读它们

  可用模式见 `lighting.AREA_MODES`：
  - 客厅：明亮、休闲、温馨、放松、休憩、观影、离开
  - 餐厅：就餐、明亮、休闲、温馨、离开
  - 卧室：明亮、休闲、温馨、放松、休憩、睡眠、离开（起夜在睡眠下由起夜规则处理）
  - 过道、卫生间、厨房、阳台、玄关等：不设区域变量，跟随全屋家庭模式
- **模式名不冲突**：模式全名 = 区域 + 模式（客厅温馨、主卧睡眠），「离开」放前面读作「离开客厅」「离开餐厅」（`mode_full_name()`），规则名、场景键名、备注卡都用全名；全屋用「全屋睡眠」，不和卧室的「睡眠」同名。生成前跑 `check_mode_names()`，并先 `mijia_read("variables", {"scope": "global"})` 确认变量 ID 和显示名没被占用。
- **模式 = 设备状态，变量同步**：
  - 执行区域模式（`build_area_mode_rule`）：先写区域模式变量，再把这个模式的亮度、色温写进「<区域>亮度」「<区域>色温」，最后按灯的角色开关这个区域的灯。
  - 人手动把区域的灯全关了（`build_area_off_sync_rule`）：区域变量改成「离开」；睡眠时不改。
  - 全屋模式带区域（`build_home_cascade_rule`）：离家 → 所有区域「离开」；全屋睡眠 → 卧室「睡眠」、其余「离开」。
- **灯光跟随**（`build_light_follow_rule(..., area="客厅")`）：模式定了以后，再有调光灯被打开（手按的、传感器开的），它直接按「客厅亮度」「客厅色温」两个变量的值亮，不会跳回上次的记忆值。规则里没有每个模式一条的支路，卡片少；以后想让灯傍晚变暖变暗，只要按时间改这两个变量。睡眠时不改灯，交给起夜。跟随全屋的区域（过道等）不传 area，读家庭模式（在家→休闲，起床、访客→明亮）。
- 智能灯的开关、亮度、色温属性按 MIoT spec 核对；接普通灯的开关键只能开关。

## 总流程

1. **读懂这个家**：拿到客户最新完整 `.bak`（MijiaFlow 下载或用户提供），加上 MijiaFlow `mijia_read(devices)`，用 `device_registry.py` 合并成 `设备台账.json`。`.bak` 只有 `did/urn`，名称和房间来自 MijiaFlow 或画布卡片；只用 `status: confirmed` 的条目。
2. **盘点现状**：列出已有规则、全局变量，以及有没有家庭模式变量。已有虚拟事件场景（如中枢网关 `siid4/eiid1` 带场景名参数）要保留，不要重复造。
3. **给客户选场景**：跑 `scene_options.py`，把 `场景选项.md` 原样发给客户，客户回复编号，只做选中的。清单是脚本按客户已有设备算出来的：同一份台账永远得到同一份清单，不靠 AI 自己想。缺设备的选项写明还差什么，不要硬套；「先问」的选项（小爱提醒）只问一次，客户说要才做。每张卡片的完整内容在 `scenes/<模板>.json` 的 `card` 字段，介绍场景时按它讲：设备条件、触发、效果（调光灯和普通灯分开说）、调试技术。
4. **填参数**：每个模板的 `params` 逐项和用户确认（模式名、按键、亮度、时间）。按键的 `eiid`、灯的开关/亮度 `siid/piid` 用 MIoT spec 和已有备份核对，不猜。
5. **生成**：调用 `scripts/scene_templates.py` 的对应函数，规则一律 `enable=False`，再 `validate`。
6. **写入**：有 MijiaFlow 时按单条规则 `set_graph`，变量用 `create_variable`，走它的计划→备份→确认语→回读流程；没有时才用全量 `.bak`（从最新完整导出合并，先给用户看差异）。启用规则只在用户明确要求时做。
7. **验证**：画布能正常渲染，执行日志里看一次真实触发；结论回报给用户。

## 家庭状态的设计原则

- 全屋家庭模式（`VhomeMode01`）值取自 `在家/离家/全屋睡眠/起床/访客`；区域里的模式放区域变量。
- **同一个按键，模式不同，功能不同**：按键事件 → `signalOr` 汇总 → `varGet(模式=A)` 成立做 A 的动作，否则（`output2`）→ `varGet(模式=B)` …… 最后接默认动作。变量节点只支持 `=`，所以只能这样逐级下沉（`mode_router()` 已封装）。
- 切换模式和执行场景分开：切换规则只写变量；每个模式一条场景规则，由 `varChange` 触发，`preload` 关闭，避免网关重启时重放。
- 起夜：卧室的区域模式=睡眠时按床头任意键，灯关着就明亮开、开着就关；同区域卫生间传感器报无人也关。不做定时自动关。
- 两种场景调用方式：要「记住现在是什么状态」用变量；只是「执行一下」用中枢网关虚拟事件（`fire_virtual_event` / `trigger_virtual_event`，`xiaomi-hub1` 实测 `siid4`，其他型号先核对）。

## 场景卡片

`scenes/index.json` 是目录，每个模板一个 JSON。除了需要的设备类型（`needs`）、可调参数（`params`）、逻辑（`logic`）和注意事项（`notes`），还有一张**场景卡片**（`card`）：

| 字段 | 内容 |
| --- | --- |
| `conditions` | 设备条件，按房间写，分必需（`required`）和可选（`optional`） |
| `match` | 给 `home_report.py` 自动匹配用：设备类别、在哪（本房间/全屋/卫生间）、数量、是否可选 |
| `trigger` | 谁按、什么时候、什么模式下生效 |
| `effect` / `effectTunable` / `effectPlain` | 效果；调光调色灯和普通灯分开写 |
| `autoOff` | 怎么自动关（没有就是 null） |
| `debug` | 调试技术：要核对的编号、常见坑、怎么验证 |

**自动化备注**：每个模板函数生成的规则，画布左上角自动带一张浅黄色备注卡，写着用途、触发、效果、自动关、设备、生成日期、技能版本和网址。客户或安装师傅打开编辑器就能看懂。设备一行用每个设备 dict 里的 `name`，所以传设备时带上台账里的名字或键名。想自己写就传 `note="文字"`，不要就传 `note=False`。

## 区域模式（明亮/休闲/温馨/放松/观影/就餐/睡眠/离开）

用 `build_area_mode_rule(rule_id, 区域, 模式, 场景键, 这个区域的灯)`。它先写「<区域>模式」变量，再按每盏灯的角色开关：调光灯设亮度色温，普通灯开或关。角色怎么判断、每个模式开哪些角色、亮度色温默认值和审美规则，都在 `references/lighting.md`。

- 用户定的原则：**温馨 = 不开主灯，打开氛围照明和补光**。
- 双控只放真正接着灯的那一路；名字带「感应」的灯不参与。
- 判断不出角色的灯会报错，AI 结合整个房间判断后给它加 `role`。
- 某个模式下灯全关（不是睡眠、离开）也会报错：用 `keep` 指定要开的灯，或建议客户加一路灯带、落地灯。
- 2.0.5 的 `build_mood_scene_rule` 还能用，但不写区域变量，新做的场景用 `build_area_mode_rule`。

## 参考案例

`examples/example_reference_cases.py` 有 7 个完整案例（占位设备）：
1. **双控**：主卧床头两个副开关（无线）切进门开关接吸顶灯的那一路，那一路保持有线。
2. **客厅温馨**：泛光灯、筒灯关；轨道灯、电视灯带、沙发灯带、落地灯开，落地灯 40%/3000K。
3. **餐厅就餐**：餐桌吊灯、筒灯、天花灯带开。
4. **客厅灯全关同步**：人手动把客厅灯全关了，客厅模式改成离开。
5. **全屋睡眠**：主卧模式改成睡眠，客厅、餐厅改成离开，并关灯。
6. **起夜**：主卧模式=睡眠时按床头键，灯关着开到明亮、开着就关；主卫无人关灯，不做定时关。
7. **回家**：开门且离家 → 家庭模式改在家 → 开玄关筒灯。

## 转换 HA 蓝图时

- 逐个输入、触发、动作对照米家节点；HA 为界面倒计时服务的计时器、重启同步通常不需要。
- `alarmClock` 卡不认星期过滤，星期和时段用 `timeRange` 接 `condition` 判断。
- 顺手找原蓝图的边界问题（如日落晚于关灯时间），在模板里修掉并写进 `notes`。

## 必须避开的坑

- 有线开关的键做模式按键前，要设为无线模式（解除继电器绑定），否则按键会先切换它自己的灯。
- 起夜、切换类动作用「先查状态再写固定开/关」，不要用猜的 toggle 动作。
- 枚举状态（人在传感器有人/无人）用 `include` + 数组，否则编辑器白屏。
- 不要把别人家的 `.bak` 或规则直接给客户导入：设备 ID 不同，而且 `.bak` 导入会整体覆盖。

## 可选：离家、睡觉前小爱提醒（先问客户）

不主动加。只在场景选项里列一行，或问一次：「离家或睡觉时，要小爱提醒你窗没关、空调还开着吗？」客户说要才做。

- `build_speaker_reminder_rule(rule_id, "离家", speaker, checks=[...], volume=40)`：家庭模式变成离家 → 逐项查（门窗传感器开着、空调开着…）→ 成立的那项让小爱说一句，一项都不成立就不说话。
- 只想说一句固定的话：不给 checks，给 `text`。想让小爱自己组织语言：给 `prompt`（例如「用一句话提醒我出门带钥匙，语气轻松」）。
- 音箱动作按 spec 核对。`xiaomi-lx06`：播报文字 siid5 aiid1；按提示词说话 siid5 aiid5（第二个参数 false = 出声）；音量 siid2 piid1（6–100）。别的型号先查 spec。
- 全屋睡眠时音量调小（`volume=30` 左右），别吵醒家人。

## 按键玩法、暂停感应、定时和保底（2.0.8）

这些都在场景选项清单里，客户选了才做。按键类的都要「空着的无线键」：设备调试时已经改成无线、还没分配用途的键。

- **一个键轮流切模式**（`build_mode_cycle_rule`）：按「<区域>模式」变量现在的值切到下一个，不另加计数器。自动跳过开的灯完全一样的模式。可以再给一个关键，按了全关，下次从第一个开始。
- **上下键调亮调暗**（`build_brightness_step_rule`）：按 休憩 → 放松 → 温馨 → 休闲 → 明亮 一档一档切，只用这个区域做得出来的模式；到头保持不变，其他状态下按任一键到温馨。同一个目标模式只生成一套灯光卡片。
- **遥控器分区控制**（`build_zone_remote_rule`）：每个区域一个开键（默认温馨）和一个关键（离开）。
- **开关分开的两个键**（`build_on_off_keys_rule`）：一个键只管开，一个键只管关，关的时候可以顺手关窗帘。
- **临时不让感应关灯**（`build_motion_pause_rule`）：全屋一个「感应暂停」变量（`motion_pause_var_definition()`）。按暂停键 → 暂停；按恢复键、指定的灯全关、离家或全屋睡眠时自动恢复。人来灯亮规则要传 `pause=True` 才会看它。客户要按区域暂停时由客户自己提出，再给每个区域加一个暂停变量。
- **定时开关**（`build_time_schedule_rule`）：每天固定时间开、关，可选星期几。
- **开着太久自动关**（`build_max_on_rule`）：开了 N 分钟还开着就关，重新打开重新计时。只给阳台、储物间、庭院、车库这类地方，卧室和起夜不用。
- **传感器低电量提醒**（`build_low_battery_rule`）：电量低于 20% 时，「低电量设备」变量（`low_battery_var_definition()`）记下设备名，有小爱就播报。没有音箱时，AI 每次读设备都先读这个变量，有值就告诉客户。电量属性编号按 spec 核对。
