# 问题反馈（用户同意后提交）

调试中遇到技能本身的问题（模板生成的规则不触发、导入报错、文档写错、缺少需要的模板），可以帮用户把问题反馈给 zhijipro.cn，用来改进本技能。**只在用户明确同意后提交，一次一条。**

## 什么时候提

- 用户说「反馈一下」「告诉作者」之类的话。
- 或者一次调试结束时，确实碰到了本技能的问题：在报告末尾问一句「要不要把这个问题匿名反馈给技能作者？」。用户没回答或说不要，就不提交，也不再追问。
- 用户自己网关、网络、设备故障这类和技能无关的问题，不反馈。

## 只发问题本身，不发家庭数据

提交前把内容整理成通用描述，**不能包含**：
- did、MAC、IP、设备型号字符串（如 `xiaomi.xxx.xxx`）、token、密码、登录码
- 客户姓名、地址、小区名、经纬度、手机号、邮箱
- 设备名称和房间名（改写成「客厅主灯」→「一个灯」、「主卧人体传感器」→「人体传感器」）
- `.bak` 内容、设备台账、完整规则 JSON

规则摘要用通用写法，例如：`人体传感器有人 → 照度<80 → 开灯；无人 statusLast 5 分钟 → 关灯`。报错只保留错误信息本身，去掉里面的节点 ID 和设备 ID。

## 提交步骤

1. 把下面要发的内容**原样**给用户看，问：「这些内容会发给 zhijipro.cn 用于改进技能，可以发送吗？」
2. 只有用户明确回答同意（如「可以」「发吧」）才发送；用户要改就改完再给他看一次。
3. 发送：`POST https://crm.zhijipro.cn/api/skill-feedback`，`Content-Type: application/json`：

```json
{
  "consent": true,
  "source": "ai",
  "category": "rule_failed",
  "skill": "mijia-home",
  "skillVersion": "2.0.9",
  "title": "一句话标题（2–120 字）",
  "summary": "发生了什么、期望什么、用的哪个模板或步骤（至少 5 字，最多 4000 字）",
  "ruleSummary": "通用写法的规则摘要（可空）",
  "errorText": "去掉 ID 后的报错原文（可空）",
  "aiClient": "你自己的名字或产品名，任何 AI 都可以填"
}
```

   `category` 取 `bug`（技能或脚本出错）、`rule_failed`（生成的规则不按预期工作）、`feature`（想要新模板或新功能）、`question`、`other`。

4. 告诉用户结果：成功就说「已提交」；返回频率限制或其他错误，就照实说，不要重试多次。
5. 不能发网络请求的 AI：把整理好的内容给用户，请用户自己到 https://zhijipro.cn/feedback/ 填写。

用户也可以随时自己去 https://zhijipro.cn/feedback/ 提交反馈。
