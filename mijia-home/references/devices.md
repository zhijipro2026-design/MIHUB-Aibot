# 灯以外的设备：空调、电视、扫地机……怎么放进场景

读设备时总会碰到灯以外的设备。规则只有三条：
1. 常见设备按下面的对照表，作为「顺带动作」挂在场景下面，让客户勾选。
2. 表里没有的设备：查说明书，用一句话告诉客户它能做什么，再问一次。
3. 安全类设备只看状态、只提醒，不放进自动控制。

`scene_options.py` 已经按这张表把顺带动作列进场景选项清单，编号带小数点（例如「离家」是 23，「离家时关空调」是 23.1）。客户回复的编号里有 23.1，才把这个动作加进离家规则。对照表在 `scripts/device_playbook.py`。

## 一、常见设备对照表

| 设备 | 场景 | 顺带动作 | 默认 | 怎么写 |
| --- | --- | --- | --- | --- |
| 空调 | 离家 | 离家时关空调 | 推荐 | 找 spec 里的开关属性（on / switch-status），写 false |
| 空调 | 全屋睡眠 | 睡觉时卧室外的空调关掉，卧室的切到睡眠模式 | 推荐 | 非卧室的写 on=false；卧室的找 mode 或 sleep-mode 属性，取「睡眠」那个值，没有就不动 |
| 空调 | 回家 | 回家时空调先开起来（用上次的温度和模式） | 客户要才勾 | 找 spec 里的开关属性（on），写 true |
| 空调 | 离开某区域 | 离开这个区域时关掉这个区域的空调 | 客户要才勾 | 找 spec 里的开关属性（on / switch-status），写 false |
| 电视 | 离家 | 离家时关电视 | 推荐 | 找 spec 里的开关属性（on / switch-status），写 false；很多电视只能关不能开，开机不放进场景 |
| 电视 | 全屋睡眠 | 睡觉时关电视 | 推荐 | 找 spec 里的开关属性（on / switch-status），写 false |
| 风扇 | 离家 | 离家时关风扇 | 推荐 | 找 spec 里的开关属性（on / switch-status），写 false |
| 空气净化器 | 全屋睡眠 | 睡觉时净化器切到睡眠模式，安静不亮灯 | 推荐 | 找 mode 属性，取「睡眠」那个值 |
| 空气净化器 | 回家 | 回家时净化器开起来 | 客户要才勾 | 找 spec 里的开关属性（on），写 true |
| 新风 | 全屋睡眠 | 睡觉时新风调到最低档或睡眠模式 | 推荐 | 找 mode 或 fan-level 属性，取「睡眠」或最低档 |
| 新风 | 离家 | 离家时新风调到最低档 | 客户要才勾 | 找 fan-level 属性，取最低档 |
| 加湿器 | 离家 | 离家时关加湿器 | 推荐 | 找 spec 里的开关属性（on / switch-status），写 false |
| 除湿机 | 离家 | 离家时关除湿机 | 客户要才勾 | 找 spec 里的开关属性（on / switch-status），写 false；梅雨天客户可能想一直开着，先问 |
| 扫地机 | 离家 | 离家时扫地机开始打扫 | 客户要才勾 | 找 start-sweep 这类动作（aiid）调用；每天只扫一次的话问客户 |
| 扫地机 | 回家 | 回家时扫地机回去充电 | 客户要才勾 | 找 start-charge / 回充 动作调用 |
| 摄像头 | 离家 | 离家时摄像头打开看家 | 客户要才勾 | 找 on 或隐私模式（privacy）属性：开摄像头、关隐私 |
| 摄像头 | 回家 | 回家时摄像头进隐私模式，不录家里人 | 客户要才勾 | 找隐私模式属性，写开 |
| 晾衣架 | 全屋睡眠 | 睡觉时关掉晾衣架的灯 | 客户要才勾 | 找 light 服务的 on 属性，写 false |
| 窗帘 | 观影 | 观影时客厅窗帘关上 | 推荐 | 窗帘的 motor-control 写关，或 target-position 写 0（按 spec） |
| 窗帘 | 全屋睡眠 | 睡觉时窗帘关上 | 推荐 | 同上 |
| 插座 | 离家 | 离家时关掉客户点名的插座（饮水机、电视插座……），冰箱、路由器的插座不关 | 客户要才勾 | 找 spec 里的开关属性（on / switch-status），写 false |

- 「推荐」的在清单里带 ⭐，客户仍可以不勾。「客户要才勾」的只列出来，不替客户决定。
- 属性编号一律按设备型号的 MIoT spec 核对（`https://home.miot-spec.com/spec/<型号>`），查不到就问客户，不猜。
- 空调「睡眠模式」、净化器「睡眠」这类取值，每个型号的数字不一样，以 spec 里的说明为准；没有这个取值就不动这台设备。

## 二、怎么写进规则

每个顺带动作是一次属性写入（或一次动作调用），用 `device_write(设备, siid, piid, 值)` 生成，放进对应场景规则的写入列表：

| 场景 | 放进哪里 |
| --- | --- |
| 离家、全屋睡眠 | `build_home_cascade_rule(..., writes=[...])` |
| 回家 | `build_arrive_home_rule(..., writes=[...])` |
| 观影、离开<区域> | `build_area_mode_rule(..., extra_writes=[...])` |
| 起床 | `build_sunrise_curtain_rule(..., writes=[...])` |

扫地机开始打扫、回充是动作（aiid），写成 `{"did","urn","siid","aiid","ins":[]}`。

## 三、单独成项的提醒和报警

用 `build_device_notify_rule(rule_id, trigger, speaker, text, volume)`：设备状态或事件 → 小爱播报。

| 设备 | 选项 | 触发（按 spec 找） |
| --- | --- | --- |
| 洗衣机 | 洗衣机洗好了，小爱提醒晾衣服 | 运行状态变成「完成」，或「完成」事件 |
| 烘干机 | 烘干机烘好了，小爱提醒收衣服 | 运行状态变成「完成」，或「完成」事件 |
| 洗碗机 | 洗碗机洗好了，小爱提醒 | 运行状态变成「完成」，或「完成」事件 |
| 燃气传感器 | 检测到燃气泄漏，小爱大声报警 | 检测到（属性为 true 或报警事件） |
| 烟雾传感器 | 检测到烟雾，小爱大声报警 | 检测到（属性为 true 或报警事件） |
| 水浸传感器 | 检测到漏水，小爱报警 | 检测到（属性为 true 或报警事件） |

- 报警类音量设到 80 以上。
- **只播报，不自动关阀门**。客户明确要求「漏水自动关水阀」时，先说明误报的后果（全家停水），客户同意后再做，并且只关不开。
- 没有小爱音箱时，这些选项标「还差设备」。

## 四、表里没有的设备

清单里「这些设备我还不熟」一栏列出了它们。对每一台：
1. 按型号查 spec，看它有哪些属性和动作。
2. 用一句话告诉客户它能做什么，再问一次：「宠物喂食器可以定时出粮、记录喂食。要放进哪个场景吗？比如离家时多喂一次」。
3. 客户说要，才按「二」的办法加进去；不要就不动。
4. 第一次碰到的类型，把查到的属性和客户的选择记进 `进度.md`。

## 五、安全类设备

燃气传感器、烟雾传感器、水浸传感器、水阀、燃气阀、门锁、取暖器、浴霸、热水器、电热毯、地暖、电热水壶、冰箱：
- 只读状态，用来判断和提醒，例如「离家时热水器还开着，要不要关」。
- 不放进场景和定时，不为测试去触发。
- 客户明确要求某个动作时，先说清风险，客户同意后再做，并在备注卡里写明「客户要求」。
